PaperFlow 에이전트 워크플로우 아키텍처

목적은 사용자 입력 3개만으로 근거 추적이 가능한 논문 패키지를 생성하는 것이다. 각 단계는 에이전트가 무작위로 움직이는 구조가 아니라, 의존성이 명시된 결정적 워크플로우 안에서 LLM/API 작업을 실행한다.

입력: 저널 정보 + 핵심 메시지 + 아웃라인 핵심: Manuscript Compiler ● 위 = 실제 구현(2026-06-23) ○ 아래 = 설계도(목표)

✅ 지금 실제로 동작 (engine/)

  • 입력 3개 → Method·Result·Intro·Conclusion 생성됨
  • 선행연구조사: OpenAlex 실제 논문 검색·인용 ✅
  • 날조 인용 가드: leak 0건 ✅
  • Result에 실제 Sobol 숫자 인용 ✅
  • figure: fal nano-banana-pro PNG 생성 ✅
  • 완성가능성 4분류 + 토큰계측 ✅

▶ 지금 실제로 동작하는 파이프라인 (engine/, 검증됨)

아래 9단계가 paperflow run <project> 한 번에 실행된다. 모듈 경로는 projects/paperflow/engine/src/paperflow/ 기준. 모델 tier는 env로 swap (지금은 deepseek가 이 환경서 TLS 막혀 gpt-5/mini로 라우팅).

아직 안 한 것(설계도엔 있음): reference entailment 검증(이 논문이 이 주장 뒷받침하나) · reviewer 6분리 · figure를 실제 데이터 플롯으로 · 프롬프트 캐싱(비용↓) · 웹UI. — 아래 "설계도"는 이 목표 전체를 그린 것이고, 위 9단계가 지금 돌아가는 실물이다.

○ 아래부터는 GPT가 그린 설계도(목표 아키텍처) — 위 실물이 이걸 향해 자란다.

1. 시스템 경계

사용자 입력 계약

MVP는 필수 입력을 아래 세 파일로 제한한다. 0_journal_info.md, 1_coremessage.md, 3_outline.md. 추가 데이터와 reference는 나중에 붙일 수 있지만, 파이프라인은 이 세 파일만으로 시작 가능해야 한다.

필수 입력 낮은 진입장벽

Manuscript Compiler

원본 파일을 project_state.json, claim graph, citation requirement, figure architecture, paragraph contract, 원고 초안, audit report로 변환한다.

단일 기준 상태 캐시 가능

최종 패키지

논문 초안, 검증된 reference, figure spec/script/prompt, reviewer report, 그리고 네 가지 완성 상태 중 하나를 생성한다.

제출 가능 또는 차단 근거 추적 가능

2. 전체 워크플로우

0입력 수집

세 입력 파일을 읽고, 메타데이터를 정규화한 뒤 run manifest와 초기 project state를 만든다.

  • 단순 파싱에는 LLM을 쓰지 않는다.
  • 캐시 키 생성을 위해 입력 hash를 만든다.

1진단

저널 제약, 연구 유형, requirement pack을 추출/선택한다.

  • 우선 biomechanics/CFD pack부터 시작한다.
  • 저널 guideline은 캐시한다.

2병렬 탐색

원고 작성 전에 독립적인 탐색 작업들을 병렬로 실행한다.

  • 선행연구 후보 탐색
  • 누락 정보 스캔
  • 초기 citation role 정의

3Gate A

Fan-in 단계: 원고 생성을 진행할지, 질문이 필요한지, 중단해야 하는지 결정한다.

  • blocking 질문과 recommended 질문을 분리한다.
  • method/data를 절대 지어내지 않는다.

4논문 구조 설계

claim graph, figure architecture, section contract, citation request ID를 만든다.

  • claim-evidence-figure-citation map 생성
  • 본문 작성 전에 paragraph contract 생성

5핵심 본문 작성

contract와 사용 가능한 근거를 바탕으로 Methods, Results, Discussion을 작성한다.

  • 섹션 간 의존성은 순차 처리한다.
  • 모르는 사실은 계속 flag로 남긴다.

6논리 검증

초안에서 claim을 다시 추출하고 contract, 근거, 섹션 의존성과 비교한다.

  • 문제가 있는 부분만 국소 수정한다.
  • 기본값은 전체 재작성 금지.

7외곽 섹션 작성

핵심 claim과 결과가 안정된 뒤 Introduction, Conclusion, Abstract를 작성한다.

  • Introduction의 과잉 약속을 막는다.
  • 확정된 contribution graph를 사용한다.

8병렬 산출물 생성

입력이 안정된 뒤 reference 검증과 figure asset/spec 생성을 병렬로 수행한다.

  • Citation verifier 실행
  • Figure script/prompt 생성

9최종 감사

reviewer mode, 저널 형식 검토, 일관성 검사, 완성 상태 분류를 수행한다.

  • 제출 가능성 label 부여
  • 자동 해결 불가능한 gap은 action item으로 남김
핵심 결정: Stage 2와 Stage 8이 주요 병렬 구간이다. Stage 4-7은 안정된 claim, figure, 결과 해석에 의존하므로 대부분 순차 처리한다.

3. 병렬 작업과 순차 작업

병렬 구간 A: 작성 전 탐색

아래 작업들은 세 입력 파일에만 의존하므로 동시에 실행할 수 있다.

선행연구 탐색

OpenAlex/Semantic Scholar/PubMed 후보 논문과 Crossref DOI metadata를 수집한다.

누락 정보 탐지

requirement pack과 사용자 입력을 비교하고 질문을 blocking/recommended/optional로 분류한다.

Citation 역할 계획

본문 작성 전에 CITREQ-* record를 생성한다.

순차 핵심: Manuscript Compiler

아래 단계들은 앞 단계 결과에 의존하므로 무작정 병렬화하면 안 된다.

Claim Graph

core message, outline, 누락 정보 상태, 초기 선행연구 맥락이 필요하다.

Section Contract

claim graph와 figure architecture가 먼저 필요하다.

핵심 본문 초안

Methods는 Results에서 쓰는 것을 정의해야 하고, Discussion은 Results를 넘어서면 안 된다.

병렬 구간 B: 작성 후 산출물 생성

claim과 figure plan이 안정되면 비용이 큰 산출물 생성 작업을 병렬로 실행한다.

Reference 확정

CITREQ-*를 검증된 논문과 BibTeX entry로 치환한다.

Figure 생성

Python plot, schematic, image prompt, caption, source manifest를 생성한다.

Reviewer 세부 모드

Methods, evidence, statistics, domain science, journal compliance, language를 분리 검토한다.

4. 의존성 매트릭스

단계 필요한 입력 병렬 가능 작업 생성물 Gate / 실패 모드
입력 수집 세 개의 markdown 파일 없음; 첫 단계 project_state.json, run_manifest.json 필수 파일 누락
저널 + 연구 유형 진단 journal info, core message, outline 기본 metadata 추출 연구 유형, requirement pack, 저널 제약 지원하지 않는 연구 유형 경고
선행연구 탐색 연구 유형, keyword, 핵심 claim 누락 정보 탐지, citation role planning 후보 논문 record, DOI metadata, evidence card 신뢰 가능한 출처 없음
누락 정보 엔진 requirement pack + 사용자 입력 선행연구 탐색 최소 질문, 완성 리스크 MISSING_CRITICAL_INFORMATION
Claim Graph core message, outline, 알려진 근거, 누락 정보 상태 주요 병렬 없음; 중앙 fan-in claim, evidence link, 허용 가능한 limitation 제공 데이터로 뒷받침되지 않는 claim
Figure Architecture claim graph + 저널 제약 citation requirement refinement figure 목록, panel message, 필요 데이터 필수 데이터 없음
원고 작성 section contract, claim graph, figure plan 의존성이 명확한 경우에만 section-local 작성 가능 citation placeholder가 포함된 원고 섹션 contract 위반
산출물 생성 + 리뷰 안정된 초안과 figure/citation request reference resolution, figure production, reviewer submode 최종 패키지와 action item EXPERT_REVIEW_REQUIRED or INSUFFICIENT_EVIDENCE

5. 핵심 데이터 객체

핵심 상태 파일

project_state.json

단일 기준 상태 파일. 사용자 입력 요약, 연구 유형, 제약, claim, 누락 정보, evidence card, figure spec, draft 상태를 담는다.

claim_graph.json

claim ID, 섹션 의존성, 필요한 근거, 허용 범위, 주장 금지 목록, 연결된 figure와 citation을 담는다.

questions.md

blocking, recommended, optional 질문을 분리한다. 사용자는 완성 가능성에 실제 영향을 주는 질문부터 본다.

run_manifest.json

입력 hash, model call, token usage, cache hit, 생성 파일, 재현성 metadata를 기록한다.

생성된 원고 산출물

section_contracts/*.json

문단 단위 contract. 목적, claim ID, evidence ID, citation role, 문단 전환, 금지 claim을 정의한다.

draft/*.md

Methods, Results, Discussion, Introduction, Conclusion, Abstract. 해결되지 않은 CITREQ-* marker는 유지한다.

references.bib + evidence_registry.json

검증된 metadata, DOI, source level, support confidence, claim-reference mapping을 담는다.

figures/figure_specs.json

panel message, 필요 데이터, plotting script, schematic prompt, caption, production status를 담는다.

6. 완성 상태 Gate

SUBMISSION_READY_DRAFT

핵심 method 정보, result claim, figure plan, reference가 모두 추적 가능하다. 사람의 문장 polish는 남을 수 있다.

EXPERT_REVIEW_REQUIRED

초안은 논리적으로 연결되어 있지만, 가정/해석/reviewer risk 판단에는 전문가 검토가 필요하다.

MISSING_CRITICAL_INFORMATION

필수 데이터, method, validation, result가 없어 방어 가능한 원고를 작성할 수 없다.

INSUFFICIENT_EVIDENCE

제공 정보나 검증된 문헌으로 claim을 뒷받침할 수 없다. 시스템은 근거를 지어내면 안 된다.

7. 모델 라우팅

작업 유형 기본 전략 상위 모델 전환 조건 비고
파싱, hashing, DOI metadata 정규화 LLM 사용 안 함 없음 결정적 코드와 API response를 사용한다.
keyword 추출, query 생성, 단순 분류 빠르고 저렴한 모델 낮은 confidence 또는 schema failure batch 병렬 처리에 적합하다.
누락 정보 탐지와 claim graph 강한 reasoning model 항상 high-stakes hallucination risk를 통제하는 핵심 단계다.
section 작성 중간급 writer model contract violation 또는 약한 논리 전체 project dump가 아니라 section-local context를 사용한다.
reviewer/audit 강한 reasoning model 항상 high-stakes methods, evidence, statistics, journal, language 검토를 분리한다.
figure production 데이터 plot은 Python, schematic은 image model 렌더링 결과가 spec과 다를 때 figure planning은 rendering보다 먼저 수행한다.
