# 페인포인트 가설: figure 디자인의 "지각적 last-mile"

**날짜:** 2026-06-02 (논문 method 작성 중 dogfooding에서 발생)
**유형:** 프로젝트 핵심 가설 (검증 깔때기 2단계에서 테스트 대상)

## 발생한 페인포인트 (1차 자료, N=1)
- method 파트를 쓰다가 "plaque classification만이 아니라 morphological parameter도
  독자에게 시각적으로 보여줘야겠다"고 **글쓰기 도중 figure 요구사항이 바뀜.**
- 그 figure를 ParaView로 만드는 데 **3시간 이상** 소요. 대부분이 수동 작업.
- 그중 카메라 각도 같은 건 **"좌표로는 말 못 하지만 마우스로는 내가 찾는다"** — 손으로만 가능.

→ 두 겹의 페인포인트:
  1. 글쓰기가 figure 요구사항을 **뒤늦게** 드러낸다.
  2. figure 실행이 **비싸고 수동**이며, 일부는 **명세 불가능하고 손으로만 가능**하다.

## 핵심 가설 (일반화)
페인포인트는 ParaView/계산분야만의 것이 아니다. **분야 무관하게 figure의
"지각적 last-mile"(색 조화, 레이아웃, 강조, 시점)은 마우스로 직접 만진다** —
말(좌표/파라미터)로 표현 못 하고 느낄 수만 있는 영역이기 때문.
ParaView 카메라 = Origin 팔레트 = Illustrator 라벨 위치 = 같은 종류의 행위.

**증거:** matplotlib/ggplot이 있어도 Origin / Prism / Excel 같은 GUI plotting 툴이
안 죽고 살아있다는 사실 자체. 전부 코드로 명세 가능했다면 멸종했어야 함.

## 두 개의 동력 (반드시 구분)
| | 동력 A: 명세 불가 (지각) | 동력 B: 코딩 불가 (접근성) |
|---|---|---|
| 예 | 카메라 각도, 색 조화, "균형 잡혀 보임" | 코드 못 짜서 Prism 씀 |
| 누구에게 | **모든 분야·모든 사람** (전문 코더도) | 코딩 못 하는 사람만 |
| 시간 지나면 | **안 사라짐** | 사라지는 중 (AI가 코드 대신 씀) |

→ **제품은 동력 A에 앵커링.** B는 AI가 침식하지만, A는 모두가 코드를 완벽히 짜는
시대에도 살아남는 방어 가능한 니즈. (사용자 본인 = 동력 B 낮고 동력 A 높은 표본.)

## 정직한 반론: "디자인 욕구"는 보편적이지 않음
- **장인형**: figure 디자인을 통제하고 싶은 craft로 봄.
- **잡일형**: 떠넘기고 싶은 chore로 봄 ("그냥 AI가 다 해줘").
- last-mile의 *존재*는 보편적이나, 그것을 즐기는지/싫어하는지는 갈림.
- 함의: 협업 모델(인간=지각, AI=계산)은 인간이 개입 안 하면 자연스럽게 full-auto로
  degrade → **같은 아키텍처가 장인형(협업)과 잡일형(자동) 둘 다 커버.**

## 리스크
지금은 **N=1 (사용자 자신, ParaView 쓰는 계산분야 1명)에서 전 분야로 추론** 중.
방향은 맞아도 *검증할 가설*이지 확정 사실이 아님. 검증 깔때기 2단계가 이 자리.

## 판별 질문 (정성 인터뷰용 — 이 한 질문이 가설을 확인/반증)
> "figure 만들 때 **마지막으로 손으로 직접 만지는 게 뭐예요?**
>  그리고 그게 **재밌어요, 짜증나요?**"

- "마지막 손질"의 답 → last-mile이 분야 무관하게 존재하는지 (동력 A 보편성)
- "재밌나/짜증나나" → 장인형 vs 잡일형 비율 (협업 수요 vs 자동 수요)
