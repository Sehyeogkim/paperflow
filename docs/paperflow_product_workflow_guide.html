사용자가 처음 제공하는 정보

초기에는 정보를 충분히 요구하는 방향으로 시작한다. 이후 실제 사용자의 이탈률과 만족도를 측정해 threshold를 조정한다.

J

Journal & User Information 필수

목표 저널, 연구 분야, 논문 제목 후보, 저자·소속 등. 저널의 형식과 논문의 문체를 정하는 입력이다.

C

Core Message 필수

“이 논문에서 가장 말하고 싶은 결과는 무엇인가?”에 대한 한 문장 또는 짧은 문단.

D

Data / Result Files + 설명 필수

CSV, XLSX, JSON, 이미지, 결과표 등. 각 파일이 무엇이고 어떤 분석에서 생성되었는지 한 줄 설명을 함께 받는다.

R

Research Plan / Related Documents 필수

연구계획서, 연구노트, 기존 Method, 발표자료, 초안, 참고문헌 PDF·BibTeX 등 연구 맥락을 제공하는 자료.

O

Outline 선택

사용자가 이미 가지고 있다면 활용한다. 없으면 Research Reconstruction Engine이 자동 생성한다.

!

중요한 원칙

사용자에게 입력을 적게 받는 것이 목표가 아니다. 초안 품질을 올리는 데 가치 있는 정보를 최대한 효율적으로 받는 것이 목표다.

Research Reconstruction Engine

업로드 파일을 단순히 요약하는 단계가 아니다. 서로 다른 자료를 하나의 연구 상태로 통합해 “이 연구가 실제로 무엇을 했는가”를 복원한다.

① Document Understanding

  • 연구문제와 목적 추출
  • 실험·해석·통계 절차 추출
  • 기존 주장과 limitation 탐지
  • 참고문헌·DOI 식별
→

② Data Profiling

  • 파일 형식과 column 분석
  • 단위·표본·변수 후보 추론
  • 사용자 설명과 파일 의미 결합
  • 주요 관찰 결과 후보 생성
→

③ Research State

  • 연구 설계와 방법
  • 데이터셋과 비교구조
  • 주요 결과 및 claim 후보
  • 알려진 정보와 unknown 분리
핵심: outline이 없더라도 Research State를 기반으로 자동 outline을 만들 수 있다. 단, 데이터만으로 의미를 확정할 수 없는 부분은 질문 단계로 넘긴다.

선행연구 조사는 두 번 수행한다

논문을 많이 모으는 것이 목적이 아니다. 연구의 구조와 Logic Graph를 완성하는 데 필요한 문헌만 찾는다.

1

Pass 1 · Field Reconstruction

이 연구가 어떤 paper archetype에 속하는지, 해당 분야 논문들이 어떤 Method·검증·Figure를 요구하는지 파악한다.

유사 논문 구조필수 보고 항목Figure/Table 패턴
2

Pass 2 · Claim-specific Search

잠정 Logic Graph의 각 claim을 기준으로 배경, 방법 정당화, 결과 비교, 해석, 반대 근거를 찾는다.

  • 이를 지지하는 Evidence

  • 해석을 정당화하는 Warrant/Reference

Graph의 역할

  • 근거 없는 문장 생성 방지
  • Method–Result–Discussion 연결 유지
  • 문단별 근거 추적
  • Figure/Table 설계의 출발점

Critical Question Loop

질문 수를 5개로 고정하지 않는다. Logic Graph에서 중요한 빈칸을 찾고, 사용자 답변 가치가 높은 순서대로 묻는다.

① Gap 탐지Claim·Evidence·Data·Method 관계에서 비어 있거나 모순된 부분을 찾는다.
② 질문 우선순위논문 방향과 reviewer risk에 미치는 영향으로 질문을 정렬한다.
③ 사용자 답변작은 batch로 질문하고 답변을 Research State에 저장한다.
④ Graph 업데이트답변을 반영해 다시 gap을 검사하고 필요하면 다음 질문을 만든다.
question_value = impact_on_primary_claim + impact_on_method_correctness + impact_on_result_interpretation + reviewer_risk - inferability_from_existing_files - user_answering_cost
질문 Loop 종료 조건: main claim이 정해지고, 각 claim에 evidence 또는 missing 상태가 명확하며, 핵심 데이터 의미·방법·해석 범위가 충분히 정의되었을 때 종료한다.

Logic Graph에서 논문으로 변환

Writer는 빈 화면에서 자유롭게 글을 쓰지 않는다. Graph를 section과 paragraph contract로 변환한 뒤 그 계약을 자연어로 compile한다.

자주 헷갈리는 질문

Logic Graph가 사용자에게 먼저 보이는 화면인가?

아니다. Logic Graph는 내부 품질 엔진이다. 사용자가 가장 먼저 보는 핵심 결과는 완성된 초안이고, Graph는 근거 추적이나 설명이 필요할 때 보조적으로 보여준다.

질문은 최대 5개인가?

아니다. 질문 수는 고정하지 않는다. 다만 한 번에 보여주는 batch는 작게 유지하며, 질문 가치와 사용자 피로도 사이 threshold를 실험한다.

선행연구는 글쓰기 직전에 한 번만 찾는가?

아니다. 분야와 논문 형식을 이해하기 위한 1차 검색, claim별 근거와 비교 연구를 찾기 위한 2차 검색으로 나눈다.

Word 파일을 읽어서 앱 오른쪽에 보여주는가?

아니다. manuscript.json이 원본이고, 여기서 DOCX와 HTML preview를 각각 생성한다.
