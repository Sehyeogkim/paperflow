⏱ 전체 시간 요약 (전부 gpt-5-mini, 실측)

  • 질문1 (진단) ≈ 141초 — 검색19 · 추출8 · normalize19 · synthesize32 · 비교+질문60
  • 논리그래프 + 빈틈 ≈ 150초 — 상태재구성58 · 그래프70 · 검사 즉시
  • 논문 생성 ≈ 126초 — auto-plan59 · contracts30(병렬) · draft34(병렬) · 출력 즉시
  • 사용자 대기 = 위 3구간 + 답변 2라운드. 컴퓨팅 합계 ≈ 7분.

🔧 속도를 만든 핵심 결정 (모델 크기 ❌ → 구조 ⭕)

  • reasoning_effort = 추론 모델의 진짜 레버. mini도 기본 medium이면 과사고 → minimal/low로 단계마다 차단.
  • 병렬화 — 추출 10편, normalize category별, contracts·draft 6섹션을 동시에. (벽시계 = 가장 느린 하나)
  • 호출 병합 — compare + questions를 한 호출로 (gpt-5 왕복 1회 제거).
  • 출력 축소 — 추출 6필드→4필드·논문당 6항목 캡; synthesize 출력 간단화.
  • 검증 OFF · 캐시 — 섹션 검증 끔(콜↓); 핵심 입력 동일하면 문헌분석 재사용(재실행 수십초↓).

⚖️ 현재 trade-off (전부 mini)

  • mini는 빠르지만 compare(보유 판정)가 더 관대 — 같은 입력에 질문 1~5개로 흔들릴 수 있음. (gpt-5 full은 일관·엄격하지만 느림)
  • 품질이 중요한 발표용은 compare·questions만 gpt-5 full + effort=low로 올리는 게 균형점.
