PaperFlow — 총 워크플로

입력 → 문헌 기반 요구 스키마 → 1차 질문 → Logic Graph → 빈틈 검사 → (조건부) 2차 질문 → 최종 Graph → 즉시 논문 생성

핵심 정의: PaperFlow는 먼저 유사 문헌에서 이 연구에 기대되는 정보 구조를 학습하고, 빠진 연구 사실을 묻고, 과학적 Logic Graph를 구성한 뒤, 남은 load-bearing 논리 연결만 추가로 물어, 완성된 그래프를 바로 논문으로 컴파일한다.

핵심 규칙

  • 질문은 최대 2라운드 — 1차(연구 사실) + 2차(논리 연결). 무한 적응 루프 금지.
  • plan 확인 게이트 제거 — 답변 → 그래프 → (조건부 2차) → 즉시 컴파일. 기존 Plan Review는 선택적 고급/디버그 뷰로만.
  • "모름" 정책 — 사실을 지어내지 않음. 영향 주장을 약화/한정/제거하고 경고 보존, 필요 시 TODO.
  • provenance — 정확한 수치 Evidence는 data/저자답변에 추적될 때만. 문헌 Source ≠ 사용자 실험 Evidence.

▲ Fallback 정책

  • 문헌 검색 실패 → 고정 requirement 팩으로 fallback (requirement_source: static_fallback 기록).
  • 잠정 그래프 생성 실패 → 1회 재시도 / Research State 최소 그래프 / 경고 후 주장 제약. 무턱대고 생성 진행 금지.
  • 2라운드 후에도 미해결 → 미지지 주장 제거 또는 한계/future work로 전환 후 가능한 가장 방어적인 논문 생성.

API 외부 상태 전이

  • POST /api/projects/diagnose (= requirement-analysis) → 1차 질문 + overall_schema
  • POST /api/projects/answers/requirement → 상태 v2 + 잠정 그래프 + 빈틈 검사 → next: logic_questions | generation
  • POST /api/projects/answers/logic → 최종 그래프 + 검증 → 즉시 생성
  • GET …/answers/{job_id}/stream → SSE 진행 (논리 구성 → 빈틈 검사 → 생성)
